테이블 레코드와 인덱스 엔트리

일반 테이블과 B-tree 인덱스에서 “레코드”와 “엔트리”가 가리키는 대상을 구분합니다.

보통은 이렇게 부릅니다

Oracle의 일반 테이블과 B-tree 인덱스를 설명할 때, 테이블 블록에 저장된 한 행은 행(row) 또는 레코드(record), 인덱스 블록에 저장된 한 항목은 인덱스 엔트리(index entry)라고 부르는 경우가 많습니다.

  • 테이블 행/레코드: 테이블 컬럼의 값을 담습니다.
  • 리프 인덱스 엔트리: 인덱스 키와 그 행을 찾는 ROWID를 담습니다.
  • 브랜치 인덱스 엔트리: 키 범위를 구분하는 키 정보와 자식 인덱스 블록의 포인터를 담습니다.

그래서 “데이터 블록에는 레코드, 인덱스 블록에는 엔트리”라고 기억하면 일반적인 Oracle B-tree 인덱스를 이해하기 쉽습니다.

엔트리는 하나, 순차는 여러 엔트리의 순서

엔트리(entry)라는 말 자체가 레코드의 순차를 뜻하지는 않습니다. 엔트리는 항목 하나를 가리키고, 여러 엔트리가 인덱스 키 순으로 놓인 상태나 그 순서대로 읽는 과정을 엔트리 순회라고 합니다.

테이블 데이터 블록          인덱스 리프 블록
  레코드/행 하나               엔트리 하나
  (id=20, name='Kim')          (key=20, ROWID=...)

테이블 행은 컬럼 값을 담고,
인덱스 엔트리는 키와 행 위치를 담습니다.

Oracle 문서에서 row directory entry라고 부르는 슬롯 정보는 또 다른 항목입니다. 이것은 블록 안에서 행이나 인덱스 엔트리의 실제 위치를 찾도록 가리키는 정보이지, 테이블 레코드나 인덱스 엔트리 그 자체가 아닙니다.

용어는 문맥에 따라 겹칠 수 있습니다

“레코드”는 구조화된 데이터 항목을 넓게 가리킬 수 있어, 어떤 자료에서는 인덱스 엔트리도 인덱스 레코드라고 부를 수 있습니다. 따라서 단어만 외우기보다 그 항목이 테이블 컬럼 값을 담는지, 인덱스 키와 ROWID 또는 하위 블록 포인터를 담는지 확인하는 것이 중요합니다.

이 구분은 일반 힙 테이블과 일반 B-tree 인덱스를 기준으로 한 설명입니다. 인덱스 구성 테이블(IOT)처럼 테이블 행 자체를 인덱스 리프에 저장하는 구조에서는 두 역할이 같은 블록 구조 안에 놓일 수 있습니다.
