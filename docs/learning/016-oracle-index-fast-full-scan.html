Index Fast Full Scan의 사용 시점

Index Full Scan과 달리 키 순서를 보존하지 않고, 인덱스 블록을 다중 블록 I/O로 읽는 이유와 조건을 정리합니다.

핵심: 인덱스를 좁은 테이블처럼 전체 읽기

Index Fast Full Scan은 인덱스의 엔트리 전체를 읽는 접근 경로입니다. 인덱스 키 순서를 따라 leaf 블록을 하나씩 연결해 읽는 대신, 블록을 저장된 순서대로 다중 블록 I/O로 읽습니다. 그래서 키 순서는 결과 순서로 보장되지 않습니다.

이 방식은 쿼리에 필요한 컬럼이 인덱스 안에 모두 있고, 그 인덱스가 테이블보다 훨씬 좁을 때 유용합니다. 테이블을 전체 스캔하는 대신 필요한 값이 들어 있는 인덱스 블록만 읽을 수 있기 때문입니다. 예를 들어 NOT NULL 키 인덱스를 이용한 COUNT(*)처럼 많은 엔트리를 읽지만 테이블의 다른 컬럼은 필요 없는 질의에서 후보가 될 수 있습니다.

요약: “순서가 중요하지 않고 인덱스만으로 결과를 만들 수 있으며, 인덱스 전체를 읽는 비용이 테이블 전체 읽기보다 낮을 때” 선택될 수 있습니다. 빠른 부분 검색이 아니라 인덱스 전체를 읽는 경로입니다.

익스텐트마다 읽는다고 보면 될까?

다중 블록 I/O는 한 번의 읽기 요청으로 여러 데이터베이스 블록을 가져오는 방식입니다. Oracle 문서는 Index Fast Full Scan을 인덱스 블록을 디스크에 놓인 순서대로 읽는다고 설명합니다. 익스텐트는 세그먼트 공간을 할당하는 단위이지만, 실행 계획의 이 연산을 “익스텐트 하나마다 정확히 한 번씩 읽는다”라고 해석할 수는 없습니다.

따라서 핵심 차이는 익스텐트 경계가 아니라 인덱스의 논리적 키 순서로 읽지 않는다는 점입니다. 실제 물리 읽기 횟수와 크기는 블록 배치, 버퍼 캐시 상태, I/O 설정 등에도 영향을 받습니다. 다중 블록 I/O라는 설명이 매번 디스크에서 실제 읽기가 발생한다는 뜻도 아닙니다.

Index Full Scan과 비교

항목Index Full ScanIndex Fast Full Scan
읽는 범위인덱스 전체인덱스 전체
읽는 순서인덱스 키 순서로 leaf 블록을 따라 읽음저장된 블록 순서로 읽으며 키 순서를 보장하지 않음
I/O 특성순서를 유지하기 위해 보통 단일 블록 I/O다중 블록 I/O 사용
정렬 활용인덱스 순서와 맞는 ORDER BY를 만족시킬 수 있음정렬 순서를 제공하지 않아 별도 정렬을 대체할 수 없음
유리한 상황인덱스 순서가 필요하거나, 인덱스만으로 전체 결과를 만들 수 있음순서는 필요 없고, 인덱스만으로 결과를 만들며, 전체 인덱스 읽기가 비용상 유리함

일반 Index Full Scan은 루트에서 첫 leaf 블록으로 내려간 뒤 leaf 연결을 따라 키 순서로 읽습니다. Fast Full Scan은 그 연결 순서를 보존할 필요가 없어 여러 블록을 한 번에 읽을 수 있습니다. 따라서 둘 다 “인덱스 전체 스캔”이지만 목적과 읽기 방식이 다릅니다.

옵티마이저가 후보로 보는 조건

  • 질의가 참조하는 컬럼이 모두 해당 인덱스에 있어야 합니다. 필요한 비인덱스 컬럼을 얻으려고 테이블을 읽는 경로가 아닙니다.
  • 결과를 인덱스 키 순서로 반환할 필요가 없어야 합니다. ORDER BY를 만족시키는 용도로는 쓸 수 없습니다.
  • 인덱스가 테이블보다 좁고, 읽을 블록 수와 비용 추정이 테이블 전체 스캔보다 유리해야 합니다. 옵티마이저는 비용을 비교해 접근 경로를 고릅니다.
  • 테이블의 모든 행을 대신 읽으려면 인덱스에 빠지는 행이 없어야 합니다. Oracle B-tree 인덱스는 모든 키 컬럼이 NULL인 행을 저장하지 않으므로, 적어도 한 키 컬럼이 NOT NULL이거나 질의 조건이 그런 행을 제외해야 합니다.

조건에 맞는 행이 적으면 필요한 구간만 읽는 Index Range Scan이 전체 인덱스를 읽는 것보다 나을 수 있습니다. 반대로 인덱스가 넓거나 테이블 읽기가 더 싸면 Table Full Scan이 선택될 수 있습니다. “순서 없이 읽으면 언제나 빠르다”가 아니라 읽기 범위와 데이터 폭을 놓고 비용을 비교하는 방식입니다.

SELECT COUNT(*) FROM orders;

SORT AGGREGATE
  INDEX FAST FULL SCAN  ORDERS_PK

이 예시는 결과에 필요한 정보를 인덱스가 제공할 수 있어 인덱스 전체 읽기가 선택된 경우를 단순화해 나타냅니다. 실제 계획은 인덱스 크기, 통계, 조건, 캐시 상태 등에 따라 달라질 수 있습니다. 실행 계획에서 INDEX FAST FULL SCAN이 보이는지, 상위에 정렬 연산이 있는지, 테이블 접근 연산이 추가됐는지를 함께 확인하면 됩니다.
