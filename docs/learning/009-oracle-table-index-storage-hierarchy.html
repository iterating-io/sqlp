테이블·인덱스의 블록 저장 관계

테이블 행과 인덱스 엔트리가 데이터 파일과 블록에 저장되는 구조를 Oracle의 세그먼트·익스텐트 계층과 함께 설명합니다.

테이블과 인덱스는 같은 저장 계층을 씁니다

Oracle에서 테이블과 인덱스는 각각 별도의 세그먼트입니다. 세그먼트는 익스텐트들로 이루어지고, 익스텐트는 여러 데이터 블록을 할당받습니다. 이 블록들은 데이터 파일에 저장됩니다.

테이블스페이스
├─ 테이블 세그먼트 → 익스텐트들 → 테이블 데이터 블록들 → 행(row piece)
└─ 인덱스 세그먼트 → 익스텐트들 → 인덱스 블록들      → 인덱스 엔트리

데이터 파일은 두 세그먼트의 익스텐트와 블록을 저장합니다.

따라서 인덱스 블록의 저장 관계가 별도로 다른 것은 아닙니다. 테이블 블록과 인덱스 블록은 모두 Oracle 블록이며, 차이는 각 블록 안에 무엇이 들어 있는지입니다.

테이블 쪽: 블록 안에 행이 있습니다

테이블 세그먼트의 블록은 테이블 행을 저장합니다. 일반 힙 테이블의 행은 공간이 있는 블록에 저장되며, 블록의 row directory가 각 행의 위치를 가리킵니다.

데이터 파일 → 블록 → 레코드라는 표현은 이런 내용물의 흐름을 간략히 말할 때 유용합니다. Oracle의 공간 할당까지 정확히 나타내려면 테이블 세그먼트와 익스텐트를 블록 앞에 넣어야 합니다.

인덱스 쪽: 블록 안에 인덱스 구조가 있습니다

인덱스 세그먼트도 같은 방식으로 익스텐트와 블록을 할당받습니다. 인덱스 블록은 트리의 루트·브랜치·리프 블록이 됩니다. 리프 블록에는 키와 행의 ROWID를 담은 엔트리가 있고, 브랜치 블록에는 검색 키 정보와 자식 인덱스 블록을 가리키는 포인터가 있습니다.

인덱스 키만으로 쿼리 결과를 얻지 못하면, 리프 엔트리의 ROWID가 가리키는 테이블 데이터 블록으로 가서 행을 읽습니다. 즉, 인덱스 블록과 테이블 데이터 블록은 별개 블록이지만 같은 데이터베이스의 저장 계층을 사용합니다.

요약: 테이블 세그먼트 → 블록 → 행, 인덱스 세그먼트 → 블록 → 인덱스 엔트리입니다. 둘 다 데이터 파일에 저장되며, 중간의 익스텐트가 블록 공간을 세그먼트에 할당합니다.

데이터 파일과 세그먼트의 관계

데이터 파일 하나에는 여러 세그먼트의 익스텐트가 들어갈 수 있습니다. 반대로 한 세그먼트의 익스텐트들은 같은 테이블스페이스 안의 여러 데이터 파일에 나뉘어 저장될 수 있습니다. 단, 하나의 익스텐트 자체는 여러 데이터 파일에 걸치지 않습니다.
