인덱스 블록과 엔트리

Oracle 인덱스 블록이 이전에 다룬 데이터 블록과 어떤 관계인지, 엔트리가 무엇을 가리키는지 정리합니다.

인덱스 블록이란?

Oracle에서 인덱스 블록은 인덱스 구조를 저장하도록 쓰이는 특별한 데이터 블록입니다. 따라서 데이터 블록과 별도의 저장 단위가 하나 더 있는 것은 아닙니다. 둘 다 Oracle이 읽고 쓰는 블록이며, 용도와 내부에 담는 정보가 다릅니다.

  • 테이블 데이터 블록: 테이블 행(row piece)을 저장합니다.
  • 인덱스 블록: 인덱스 키와 그에 연결된 위치 정보, 또는 트리의 다음 블록을 가리키는 정보를 저장합니다.

이전 학습에서 “블록”이라고 할 때는 보통 Oracle 데이터 블록이라는 공통 단위를 말했습니다. 그중 테이블 행이 든 블록을 가리키려면 테이블 데이터 블록, 인덱스 구조를 담은 블록은 인덱스 블록이라고 구분하면 됩니다.

엔트리는 순서가 아니라 항목 하나

엔트리(entry)는 인덱스 블록에 저장된 항목 하나를 말합니다. 리프 블록의 인덱스 엔트리는 인덱스 키와 그 행을 찾는 ROWID로 이루어집니다. 브랜치 블록의 엔트리는 검색할 키 범위를 나타내는 키 정보와 자식 블록 포인터를 가집니다.

리프 블록
  엔트리 1: (key=10, ROWID=A)
  엔트리 2: (key=20, ROWID=B)
  엔트리 3: (key=30, ROWID=C)

각 괄호가 엔트리 하나이고,
이 엔트리들이 키 순서로 놓인 전체가 순차입니다.

여기서 말하는 인덱스 엔트리와 row directory 엔트리는 다른 것입니다. 인덱스 엔트리는 키와 ROWID 같은 인덱스 정보를 담고, row directory 엔트리는 블록 안에서 해당 항목의 실제 위치를 가리키는 슬롯입니다.

짧게 말하면, 엔트리는 “항목 하나”, 엔트리 순서는 “그 항목들을 키 기준으로 읽는 순서”입니다.

인덱스 스캔에서의 관계

수직 탐색은 루트와 브랜치 블록을 따라 시작 리프 블록을 찾습니다. 수평 탐색은 그 리프 블록 안의 엔트리를 순회하고, 범위가 이어지면 다음 리프 블록으로 넘어갑니다. 따라서 수평 탐색은 “엔트리들의 순서를 읽는 것”이며, 엔트리 하나와 같은 뜻은 아닙니다.
