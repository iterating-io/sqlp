인덱스 블록·ROWID와 B+·B* 트리

Oracle의 인덱스 노드와 블록, 엔트리 정렬, ROWID, 데이터 블록을 구분하고 B+·B* 트리 용어를 정리합니다.

인덱스 트리의 노드는 블록인가?

Oracle B-tree 인덱스 그림에서 각 노드는 보통 하나의 인덱스 블록을 나타냅니다. 루트 블록에서 브랜치 블록을 거쳐 리프 블록으로 내려가며, 브랜치 블록은 하위 블록을 가리키고 리프 블록은 인덱스 키와 행 위치 정보를 담습니다. 따라서 Oracle 구조를 설명할 때는 “노드 하나가 인덱스 블록 하나”로 이해해도 됩니다.

블록 안에서 무엇을 기준으로 정렬할까?

정렬 기준은 블록의 종류와 그 안에서 말하는 엔트리에 따라 다릅니다.

  • 인덱스 리프 엔트리: 인덱스 키 순으로 정렬합니다. 비고유 인덱스에서 같은 키가 여러 행에 있으면 ROWID가 보조 정렬 기준이 됩니다.
  • 인덱스 블록 내부: 엔트리 본문은 물리적으로 키 순서대로 연속 배치되지 않습니다. 대신 row directory가 키 순으로 정렬되어 있어 논리적으로 그 순서대로 찾고 순회합니다.
  • 테이블 데이터 블록: ROWID의 행 번호는 row directory의 슬롯을 가리킵니다. 이는 정렬 순서가 아니며, 테이블 행이 ROWID 순으로 저장된다는 뜻도 아닙니다.
따라서 “블록 안 레코드가 ROWID 순으로 정렬된다”라고 일반화하기보다, “인덱스 리프는 키 순이며 같은 키 안에서 ROWID 순”이라고 구분하면 정확합니다.

ROWID와 파일·블록·행

Oracle의 물리적 ROWID는 행을 찾는 주소입니다. 확장 ROWID에는 데이터 객체 번호, 테이블스페이스 기준 데이터 파일 번호, 그 파일 안의 블록 번호, 블록 안의 행 번호가 들어갑니다. 마지막 행 번호는 블록의 row directory 슬롯을 가리키며, 첫 슬롯 번호는 0입니다.

데이터 파일은 Oracle 데이터 블록들로 이루어지고, 테이블 행은 데이터 블록에 저장됩니다. 다만 블록은 행만으로 이루어지지 않습니다. 블록 헤더, 디렉터리, 여유 공간, 행 데이터 등이 들어갑니다. 한 행이 한 블록에 들어가지 않거나 갱신 후 블록에 맞지 않으면 여러 row piece로 나뉘어 저장될 수도 있습니다.

B+ 트리와 B* 트리

  • B+ 트리: 내부 노드는 검색 경로를 정하는 구분 키와 자식 포인터를 두고, 데이터 레코드 또는 레코드를 가리키는 포인터는 리프에 둡니다. 리프끼리 연결해 범위 검색을 효율적으로 할 수 있습니다.
  • B* 트리: 일반적인 정의에서는 노드가 가득 찼을 때 바로 나누기보다 형제 노드와 키를 먼저 재분배합니다. 형제도 가득 차면 노드 두 개를 세 개로 나누어, 루트를 제외한 노드가 대략 2/3 이상 차도록 공간 사용률을 높입니다.

두 이름은 비교하는 관점이 다릅니다. B+는 데이터 항목을 어느 층에 두고 리프를 어떻게 연결하는지에, B*는 형제 재분배와 노드 점유율을 높이는 분할 규칙에 초점을 둡니다. 그래서 문맥 없이 두 이름을 서로 완전히 다른 구조의 대립으로 단정하기 어렵고, 교재마다 B*의 분류 방식도 다를 수 있습니다.

Oracle 공식 문서는 기본 인덱스를 “B-tree index”라고 부르며 루트·브랜치·리프 블록과 리프의 키·ROWID 구조를 설명합니다. 일반 Oracle 인덱스를 B* 트리라고 단정하거나, 2/3 점유율 보장을 가정하지 않는 편이 안전합니다.
