옵션 조건과 인덱스 범위 스캔

OR, LIKE, BETWEEN과 복합 인덱스를 함께 볼 때, 인덱스가 쓰이는지뿐 아니라 실제로 얼마나 읽는지를 판단합니다.

범위 스캔 자체가 비효율은 아니다

BETWEEN이나 LIKE 'ABC%'는 인덱스에서 일정한 키 범위를 읽는 범위 스캔으로 처리될 수 있습니다. 범위가 좁으면 효율적입니다. 조건에 맞는 행이 많아 인덱스 항목을 많이 읽고 테이블도 많이 방문해야 할 때는 전체 테이블 스캔이 더 저렴할 수 있습니다.

판단 기준은 “범위 스캔인가?”가 아니라 “인덱스에서 몇 항목을 읽고, 테이블 블록을 얼마나 방문하는가?”입니다.

선택 조건을 OR로 표현한 경우

SELECT *
FROM 거래
WHERE (:cust_id IS NULL OR 고객ID = :cust_id)
  AND 거래일자 BETWEEN :dt1 AND :dt2;

:cust_id가 NULL이면 고객 ID 조건이 사라지고 날짜 범위의 거래를 모두 조회합니다. 이 갈래에서는 고객 ID 인덱스로 특정 고객을 찾을 수 없습니다. 그래서 책의 실행 계획처럼 TABLE ACCESS FULL이 선택될 수 있습니다.

이 패턴은 NULL일 때 옵션 컬럼 값이 NULL인 행까지 포함하는 의미를 보존한다는 장점이 있습니다. 반면 고객ID = NVL(:cust_id, 고객ID)로 단순 치환하면, 옵션 값이 NULL일 때 고객ID 자체가 NULL인 행은 비교 결과가 참이 아니어서 빠질 수 있습니다. 조건식을 바꿀 때는 성능뿐 아니라 결과가 같은지도 확인해야 합니다.

OR-Expansion이 유리한 경우

SELECT *
FROM 거래
WHERE 고객ID = :cust_id
  AND ((:dt_type = 'A' AND 거래일자 BETWEEN :dt1 AND :dt2)
    OR (:dt_type = 'B' AND 결제일자 BETWEEN :dt1 AND :dt2));

이 쿼리는 OR의 두 갈래 모두 고객ID = :cust_id로 행을 좁힙니다. 인덱스가 각각 (고객ID, 거래일자), (고객ID, 결제일자)라면 옵티마이저가 OR을 갈래별로 나누는 OR-Expansion을 선택할 수 있습니다.

책의 실행 계획에서 CONCATENATION은 나뉜 갈래의 결과를 합치는 단계이고, 각 갈래의 INDEX RANGE SCAN은 해당 복합 인덱스를 읽는 단계입니다. 이 사례는 OR이 있어도 각 갈래에 알맞은 인덱스 접근이 가능함을 보여줍니다.

앞의 NULL 옵션 조건과 차이는 OR 문법 자체가 아닙니다. 첫 예제의 NULL 갈래에는 고객 ID로 좁힐 조건이 없지만, 이 예제는 두 갈래 모두 고객 ID 조건을 유지합니다.

LIKE 옵션 조건: 선두 조건의 선택도가 중요하다

인덱스가 (상품명, 상품분류코드)일 때 다음 조건은 상품명으로 먼저 좁힌 뒤, 분류 코드의 접두어 범위를 찾을 수 있습니다.

WHERE 상품명 = :prd_nm
  AND 상품분류코드 LIKE :prd_cls_cd || '%'

상품명이 소수의 행만 찾는 선택도 높은 조건이라면 인덱스가 효율적일 가능성이 큽니다. LIKE 'ABC%'처럼 앞부분이 정해진 패턴은 범위 스캔이 가능하지만, LIKE '%ABC'는 보통 같은 방식으로 시작 범위를 정하기 어렵습니다.

반대로 필수 조건이 많은 행을 반환한다면, 옵션 조건이 빠지거나 매우 넓은 패턴일 때 인덱스 범위도 커질 수 있습니다. 예를 들어 (상품대분류코드, 상품코드)에서 대분류만으로 수만 행이 선택된다면, 인덱스를 훑고 각 ROWID로 테이블을 방문하는 것보다 전체 테이블 스캔이 나을 수 있습니다.

옵션 값이 실제로 들어오는 경우에 맞는 실행계획이 값이 없거나 넓은 패턴일 때도 빠르다고 보장되지는 않습니다. 바인드 값과 데이터 분포에 따라 예상 행 수와 실제 행 수가 달라질 수 있으므로 실행 통계를 확인합니다.

복합 인덱스 중간 컬럼이 빠진 경우

(A, B, C) 인덱스는 먼저 A, 그 안에서 B, 그 안에서 C 순으로 정렬되어 있습니다.

-- 선두 키와 중간 키로 위치를 좁히고 C 범위를 탐색
WHERE A = 10 AND B = 20 AND C BETWEEN 5 AND 9

-- B가 빠져 C 값들이 B별 구간에 흩어질 수 있음
WHERE A = 10 AND C BETWEEN 5 AND 9

두 번째 조건에서는 일반적인 범위 스캔이 보통 A = 10인 구간을 읽고, C 조건은 인덱스 항목에 대한 필터로 적용합니다. C가 인덱스에 있으므로 테이블 방문 전에 일부 행을 걸러낼 수는 있지만, 인덱스에서 읽는 항목 자체를 크게 줄이지는 못할 수 있습니다.

Oracle의 인덱스 스킵 스캔처럼 B의 값별 구간을 나누어 탐색하는 예외가 있습니다. 다만 비용이 유리할 때 선택되는 대안이지, 빠진 중간 컬럼을 항상 무시하고 C만으로 연속 범위를 찾는다는 뜻은 아닙니다.

한눈에 정리

  • 범위 스캔은 LIKE 접두어 검색이나 BETWEEN에서 자연스러운 인덱스 접근 방식이며, 범위가 좁으면 효율적입니다.
  • 범위가 넓고 많은 행을 읽으면 테이블 전체 스캔이 더 빠를 수 있습니다.
  • OR도 각 갈래가 인덱스로 좁혀지면 OR-Expansion으로 효율적으로 실행될 수 있습니다.
  • 복합 인덱스의 중간 컬럼이 빠지면 후행 컬럼은 보통 범위 시작점을 정하기보다 필터로 쓰입니다. Skip Scan은 예외적인 대안입니다.
