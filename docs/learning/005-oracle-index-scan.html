인덱스의 수직 탐색과 수평 탐색

Oracle B-tree 인덱스 범위 스캔에서 시작 위치를 찾고, 필요한 키들을 읽는 흐름을 정리합니다.

수직 탐색: 시작 리프 블록 찾기

인덱스는 루트 블록, 브랜치 블록, 리프 블록으로 이루어집니다. 수직 탐색은 루트에서 브랜치들을 따라 내려가 조건을 만족하는 첫 인덱스 엔트리가 있는 리프 블록을 찾는 과정입니다. 범위 조건에서는 보통 하한값 이상인 첫 키의 위치를 찾습니다.

수평 탐색: 리프 엔트리를 이어 읽기

시작 위치를 찾으면 각 리프 블록 안에서 인덱스 엔트리를 키 순서로 읽고, 블록 경계에서는 서로 연결된 다음 리프 블록으로 이동합니다. 따라서 수평 탐색은 블록 안의 엔트리 순회와 리프 블록 간 이동으로 설명할 수 있습니다. 블록 번호나 데이터 파일의 물리적 위치 순서라는 뜻은 아닙니다.

Oracle은 블록 본문에 엔트리를 키 순서대로 연속 배치하지 않습니다. 대신 블록의 row directory가 키 순으로 정렬되어 있어, 엔트리를 논리적으로 키 순서대로 찾고 순회합니다.

수직 탐색:  루트 → 브랜치 → 시작 리프
                                  │
수평 탐색:  [20, 22] ↔ [25, 28] ↔ [30, 35]
             └────── 인덱스 키 순으로 연결된 리프 블록 ──────┘

WHERE key BETWEEN 20 AND 30 이라면
20부터 30까지 읽고, 범위 밖의 다음 키에서 멈춥니다.

같은 키가 여러 행에 걸리면 Oracle 인덱스 엔트리는 키와 ROWID를 함께 사용해 정렬합니다. 따라서 이 문맥에서 “블록 내 레코드 순”이라는 표현은 맞습니다. 여기서 레코드는 리프 블록의 인덱스 엔트리를 뜻하며, 그 논리적 순서는 키와 ROWID 기준입니다.

수평 탐색과 인덱스 스캔의 관계

수평 탐색만을 인덱스 스캔 전체와 같은 말로 보기는 어렵습니다. 인덱스 범위 스캔은 먼저 수직으로 시작 리프를 찾고, 이어서 수평으로 범위의 리프 엔트리를 읽습니다. 일반적으로 “인덱스 스캔”은 이 접근 작업을 가리키는 더 넓은 말이고, 수평 탐색은 그중 리프를 순회하는 단계입니다.

쿼리가 인덱스에 없는 컬럼도 요구하면 스캔한 엔트리의 ROWID를 이용해 테이블 블록에서 행을 읽을 수 있습니다. 스캔 방향은 오름차순 또는 내림차순일 수 있습니다.

요약: 수직 탐색은 “어디서 시작할까?”, 수평 탐색은 “시작점부터 어떤 인덱스 키를 읽을까?”에 답합니다.
