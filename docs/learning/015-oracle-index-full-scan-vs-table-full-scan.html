Index Full Scan과 Table Full Scan

인덱스가 좁은 데이터 집합이라는 장점과 ROWID 테이블 접근 비용을 함께 비교합니다.

큰 방향은 맞다: 인덱스가 더 좁을 수 있다

테이블 행에는 모든 컬럼 값이 있지만, B-tree 인덱스 엔트리에는 인덱스 키와 ROWID가 중심으로 들어갑니다. 키가 테이블 행보다 좁으면 인덱스 블록 하나에 더 많은 엔트리가 들어가므로, 필요한 컬럼이 인덱스 안에 모두 있을 때 인덱스만 읽는 편이 테이블 전체보다 적은 블록을 읽을 수 있습니다.

필요한 조회 컬럼과 조건 컬럼이 인덱스에 모두 포함되어 테이블에 가지 않고 결과를 만들 수 있는 경우를 흔히 covering 또는 index-only 접근이라고 합니다. 인덱스에 없는 컬럼이 필요하면 각 결과 엔트리의 ROWID로 테이블 행도 가져옵니다. 따라서 거의 모든 행을 반환하는 비커버링 질의라면, 인덱스 엔트리를 거의 전부 읽는 데 더해 결과 엔트리 대부분의 ROWID로 테이블 블록도 방문하는 비용이 붙습니다. ROWID 접근은 묶어서 처리될 수 있지만, 테이블 블록을 한 번 훑는 Table Full Scan보다 비싸질 수 있습니다.

INDEX FULL SCAN
  → 인덱스 엔트리에서 ROWID 획득
  → TABLE ACCESS BY INDEX ROWID로 필요한 테이블 행 접근

TABLE ACCESS FULL
  → 테이블의 포맷된 블록을 한 번 순차적으로 읽고 조건 적용

첫 번째 계획은 인덱스 스캔과 ROWID 기반 테이블 접근이 함께 있는 경로이지, 실행 계획 연산자 자체가 TABLE ACCESS FULL인 것은 아닙니다. 다만 조건에 맞는 행이 거의 전체이고 ROWID가 여러 블록에 흩어져 있으면 사실상 테이블의 많은 블록을 다시 찾아가게 됩니다. 이 경우 Table Full Scan은 각 테이블 블록을 한 번 읽고 인접 블록을 묶어 읽을 수 있어 더 효율적일 수 있습니다.

세 가지 전체 스캔 경로를 구분하기

접근 경로읽는 방식주요 장점과 제한
Table Full Scan테이블의 포맷된 블록을 읽고 조건에 맞지 않는 행을 걸러냅니다. 인접 블록을 여러 개씩 읽을 수 있습니다.많은 행과 컬럼을 읽는 경우, ROWID를 따라 여러 블록을 따로 찾는 것보다 유리할 수 있습니다. SQL 결과 순서는 보장하지 않습니다.
Index Full Scan인덱스 전체를 키 순서대로 읽습니다. Oracle은 leaf 블록을 순서대로 읽으며 일반적으로 단일 블록 I/O를 사용합니다.정렬 순서가 필요하거나 인덱스만으로 조회를 끝낼 수 있으면 유리할 수 있습니다. 빠진 컬럼이 필요하면 ROWID로 테이블도 읽습니다.
Index Fast Full Scan인덱스 블록을 디스크에 놓인 순서로 여러 블록씩 읽습니다. 인덱스를 좁은 테이블처럼 취급합니다.쿼리에 필요한 컬럼이 인덱스 안에 있어야 합니다. 모든 행을 대체하려면 인덱스의 모든 키가 NULL인 행이 결과에서 제외된다는 조건도 필요합니다. 키 순서를 보장하지 않아 ORDER BY 정렬을 대신할 수 없습니다.

많은 행을 읽을수록 항상 Table Full Scan일까?

인덱스가 필요한 컬럼을 포함하지 않고, 조건에 맞는 행이 테이블 곳곳에 많이 흩어져 있다면 인덱스 엔트리마다 ROWID로 테이블을 찾는 비용이 커집니다. 이때는 테이블 블록을 순차적으로 읽는 Table Full Scan이 더 쌀 수 있습니다. 선택도가 낮고 인덱스의 클러스터링 팩터가 좋지 않을수록 이런 판단이 쉬워집니다.

반대로 쿼리에 필요한 컬럼이 모두 좁은 인덱스 안에 있으면, 결과가 테이블 행 대부분에 해당하더라도 인덱스 전체 스캔이 더 적은 블록을 읽을 수 있습니다. 정렬된 결과가 필요하면 일반 Index Full Scan이 별도 정렬을 피할 수도 있습니다. 따라서 “전체에 가까우면 인덱스는 항상 비효율적”이라고 단정할 수 없고, 실제 읽을 블록 수와 테이블 재접근 비용을 비교해야 합니다.

요약: 넓은 범위를 읽는 비커버링 인덱스는 ROWID 테이블 접근 때문에 Table Full Scan보다 비쌀 수 있습니다. 커버링 인덱스라면 Index Full Scan 또는 Index Fast Full Scan이 여전히 유리할 수 있습니다.

실행 계획에서 확인하기

  • TABLE ACCESS FULL: 테이블 블록을 전체 스캔합니다.
  • INDEX FULL SCAN: 인덱스를 순서대로 모두 읽습니다. 상위 단계에 TABLE ACCESS BY INDEX ROWID가 있으면 테이블 행도 가져옵니다.
  • INDEX FAST FULL SCAN: 인덱스 블록을 순서 없이 빠르게 읽습니다. 이 경로는 인덱스만으로 쿼리에 필요한 값을 제공할 수 있어야 합니다.
